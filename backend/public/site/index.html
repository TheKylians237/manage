UNE VUE CLAIRE, POUR CHAQUE MÉTIER

Du mouvement de stock au rapport d’intervention.

Les équipes partagent les mêmes informations, avec des accès définis selon leur responsabilité.

01

Inventaire organisé

Références, catégories, seuils minimums, emplacements et états opérationnels réunis dans un inventaire consultable.

02

Stock qui suit le terrain

Entrées, sorties, transferts et dotations sont inscrits dans un journal. Les mouvements de matériel restent consultables.

03

Maintenance coordonnée

Planifiez ou démarrez une intervention, renseignez diagnostic et conclusion. Les transferts vers le maintenancier suivent le cycle de maintenance.

04

Rappels au bon moment

Le maintenancier reçoit un e-mail environ cinq minutes avant l’intervention planifiée. Les alertes du navigateur complètent le rappel.

05

Statistiques lisibles

Les tableaux de bord présentent stocks, mouvements et maintenances par jour, semaine, mois ou année.

06

Suivi des équipes

Le superviseur consulte les indicateurs, les mouvements détaillés et les évaluations journalières sur cinq.

07

Comptes protégés

Les droits dépendent du rôle. La connexion demande un mot de passe et un second facteur TOTP.

08

Traçabilité et préférences

Les historiques personnels et le journal administrateur facilitent le suivi. Le mode clair ou sombre se règle dans le profil.

AVANT L’INSTALLATION

Les prérequis

Mat-Manage est une application web centralisée : seul le serveur héberge Node.js et la base de données.

Sur le serveur

Windows 10/11 ou Windows Server, Node.js 20 ou supérieur, npm, et MySQL 8 ou MariaDB compatible. Prévoyez un compte SQL dédié, les droits nécessaires pour importer le schéma, et un dossier de données sauvegardé.

Sur chaque poste utilisateur

Un navigateur récent avec JavaScript et cookies activés, un accès au même réseau local, et une application d’authentification TOTP (Microsoft Authenticator, Google Authenticator ou équivalent) pour le second facteur.

Réseau et services

Le serveur et MySQL doivent rester démarrés. Autorisez le port TCP 3000 sur le profil réseau privé et utilisez l’adresse IP stable du serveur. SMTP est requis pour les e-mails et rappels, mais pas pour consulter l’application. En HTTP sur le LAN, les identifiants ne sont pas chiffrés ; utilisez HTTPS dès que possible.

Sécurité et accès distant

Définissez des secrets uniques dans backend/.env. La liste blanche IP est configurée dans TRUSTED_CLIENT_CIDRS. Pour un accès depuis Internet, ajoutez HTTPS et un reverse proxy correctement configuré.

GUIDE D’UTILISATION

Prêt à démarrer ? Voici le parcours.

Pour l’équipe informatique qui installe le serveur et les utilisateurs qui prennent l’application en main.

01

Installer le serveur

Sur le poste serveur Windows, installez Node.js et MySQL/MariaDB. Téléchargez le paquet, extrayez-le, puis configurez backend/.env à partir du modèle fourni.

Créez la base, appliquez dans l’ordre les scripts SQL du guide d’installation, puis installez les dépendances depuis le dossier backend avec npm ci.

02

Lancer et partager l’adresse

Démarrez le serveur avec npm start. Il écoute sur les interfaces réseau et affiche les adresses disponibles. Sur les autres appareils du même réseau, ouvrez http://ADRESSE-DU-SERVEUR:3000.

Autorisez Node.js ou le port TCP 3000 dans le pare-feu Windows sur le réseau privé. Gardez le serveur et la base démarrés.

03

Créer et sécuriser les comptes

L’inscription publique peut être activée ou désactivée par l’administrateur. Celui-ci peut créer les comptes, choisir le mot de passe initial et l’envoyer à l’adresse indiquée.

À la première connexion, chaque personne configure son application TOTP et conserve ses codes de récupération.

04

Suivre son activité

Le magasinier enregistre les entrées, sorties et dotations. Le maintenancier consulte ses interventions, documente le diagnostic et clôture avec une conclusion.

Les responsables filtrent l’activité et les dates ; les tableaux se mettent à jour au changement de critère.

Pour recevoir les e-mailsConfigurez le serveur SMTP dans backend/.env. Pour les liens de réinitialisation envoyés aux personnes du réseau local, renseignez aussi APP_PUBLIC_ORIGIN avec l’adresse stable du serveur.
